# 峡谷矿工营地精修 PRD／资产制作规格 v1.0

日期：2026-11-15  
状态：制作前拆解，供用户先审阅；尚未开始地图改造。  
对象：原工程《晶脉峡谷_三区矿洞初稿.rbxlx》，继续在原工程迭代。  
制作原则：先 Roblox 原生局部样板 → 实机对照 → 必要部件转 Blender → 整图组合。

## 1. 本轮要交付什么

把已认可的营地概念稿拆成实际可制作、可替换、可验收的资产。目标是卡通夸张、明亮、有厚度和材质层次的沙漠矿工营地。

第一张概念稿控制布局、体量和远近层次；第二张控制岩壁和地砖近景。概念稿不是精确施工图，出现比例冲突时，以实际角色、可走空间、交互距离为准，并在实施记录中说明差异。

本轮视觉优先级：

1. 连续、厚重、分层的围墙轮廓。
2. 冷灰地面与暖橙岩壁的色彩分离，清楚的地砖明暗和路缘厚度。
3. 设施与角色尺度合适，减少“大空台子上放小物件”。
4. 矿洞、标牌、摊位形成中景；细节服务大形体。
5. 木纹、斑点、铆钉、植物等次级细节最后做。

不新增玩法、音乐、战斗数值或排行榜类别。现有三款练习石、NPC质感、玩家自带穿着、铁镐及挥镐逻辑继续使用。图中三块榜板是美术构图示意，当前代码只有力量榜和金币榜，本轮保留两个数据榜，不为了凑图增加第三项系统。

## 3. Roblox 还是 Blender：按部件选，不整图押注一种工具

Roblox 原生建造包括 Part、WedgePart、CornerWedgePart、材质、贴图、SurfaceGui，以及少量编辑期实体建模。原生制作不意味着只用纯色塑料块，也不意味着所有纹理都堆成小零件。

| 部件 | 第一制作路径 | Blender触发条件 |
|---|---|---|
| 十字主路、路缘、台阶、平台 | Roblox Part组合，明显轮廓处少量楔形切角 | 只有重复使用的复杂倒角砖确实无法简化时转一个模板 |
| 连续砂岩围墙 | 大块Part＋楔块收形＋编辑期局部CSG试做 | 外轮廓仍像积木／圆柱；拼缝密集；修形零件失控；需要连续斜面和独立UV |
| 木柱、横梁、斜撑、包铁、螺栓 | Roblox原生；同类模板复用 | 特写轮廓确实需要较复杂切削时局部转模 |
| 摊棚 | 先改现有模板；大块倾斜条带／少量分段形成布面垂度 | 仍像硬台阶板；布边轮廓不自然；零件过多，转一个共享篷布网格 |
| 矿洞口 | 原生粗木框、斜撑、铁件；岩肩复用岩壁模块 | 只把不规则岩肩／拱顶转网格，保留原生木构 |
| 广告牌／排行榜 | Roblox框体＋SurfaceGui文字 | 不为文字、榜单和简单框体使用Blender |
| 草丛／小石／箱子／路灯 | 原生小模板试做，控制重复和数量 | 只有样板证明原生轮廓不合格才替换单项 |
| 三款练习石、铁镐、NPC | 直接复用已认可资产 | 不在本轮重新制作 |
| 绿框及交互范围 | 复用现有ZoneVisuals和AutoSellZone | 不使用Blender |

技术依据：Roblox支持零件组合和实体建模；MaterialVariant适合复用材质，SurfaceAppearance用于带UV的MeshPart。两者不能当作同一种挂法。详见文末官方文档。

## 4. 空间与尺度草案

坐标约定：+Z入口方向；-Z矿洞方向；-X练习区；+X排行榜；原点为十字中心。以下均为样板后可调整的初始目标，单位studs。

| 部位 | 初始目标 | 必须保持的关系 |
|---|---|---|
| 营地主要内场 | 约216×216；常规岩壁内缘约±108 | 不是所有位置都可走；四角岩肩向内凸 |
| 含岩壁外轮廓 | 约252～272，取决于岩壁厚度 | 与“216内场”分开记录 |
| 岩壁高度 | 普通段34～46；少量高点约50 | 避免全圈等高，最高点不均匀撒满 |
| 中央十字主路 | 净宽26～28；局部节点略宽 | 玩家主视线直指矿洞 |
| 四个摊位中心 | 初步(±30, ±30) | 货摊面朝十字或中心斜向；台阶和光区不侵占主路 |
| 摊位视觉尺寸 | 约宽13～15、高10～11、主体深8～10 | 建筑外壳可放大，NPC不跟着放大 |
| 练习区台地 | 中心约(-74,0,0)，约28×82 | 左侧凹位；上方牌不挡矿洞方向 |
| 练习石中心 | x约-74；z约+22、0、-22；正面朝+X | 三块已认可石头保持原尺寸与辨识度 |
| 单个练习站 | 初步约14×16 | 需容纳玩家站位与挥镐，不能只按石头轮廓缩 |
| 排行榜台地 | 中心约(74,0,0)，约30×68 | 两块数据榜共享大框体，上方统一标题 |
| 矿洞门槛 | 初步(0,0,-100)；净宽约26～28 | 与实际三层矿洞入口一起平移，不能只有门头挪走 |
| 出生点 | 初步(0,0,84)附近 | 落地不在触发区内，能看见方向牌和矿洞 |

不采用整张地图统一ScaleTo。具体移动的是设施挂点、建筑外壳和路网尺寸，玩家、矿石、特效高度分别处理。

现阶段不承诺图中每一处透视比例都能同时成立。先在玩家真实镜头下检查，再锁最终尺寸。主路不必等比例变宽；新增面积主要给墙脚退让、侧区台地和景深。

## 5. 围墙制作分解：最重要的试做对象

### 5.1 资产族

- CanyonWall_Straight_A/B/C：长约24～32，深约12～18，高约28～40；3个基础剪影。
- CanyonWall_Corner：转角段，主岩肩向场内伸出约10～16。
- CanyonWall_Buttress：宽约20～30、深约16～24，承担四角内凸形态。
- CanyonWall_UpperLedge：上层台阶岩，宽约14～24，单层高度6～12。
- CanyonWall_PortalShoulder：矿洞两侧岩肩，门口留净空。
- CanyonWall_Cap：少量顶部收形块，不能满圈叠小碎石。

### 5.2 每一段从大到小怎么做

1. 一个主岩体确定宽高比和厚度，先看纯灰剪影。
2. 叠入2～3个宽大层面；层与层前后错开1～3，避免像规则砖墙。
3. 顶面用楔块形成少量斜坡和缺角，侧面以宽斜面收形；不是给每条边都包一圈细条。
4. 至少保留一个大而完整的可读立面，约占主可见面的40%～60%。
5. 接缝位置藏在转折／阴影侧；邻段有限互穿消除漏缝，不让两张外露表面共面。
6. 横向岩层纹用材质或少量大形体表达；细裂纹不使用大量黑线Part。
7. 相邻模块按A/B/C节奏、有限偏转和少量宽度变化组合。非等比缩放控制在小范围，不再把小矿石拉成高墙。
8. 视觉岩壁与阻挡碰撞分开；碰撞用少量厚实Box／Wedge代理，不能堵住正常走路范围。

### 5.3 色材目标

- 主面参考：暖橙 #CF713D；受光面 #E98B4C；阴影面 #995338。
- 同一大面内部允许轻微低频变化，不给每个小面随意换颜色。
- 先试内置Sandstone；如果纹理尺度、色调或写实程度不匹配，补一套可平铺的克制层岩材质。
- 自定义纹理初始1024²；每约12～20 studs一个主要纹理周期，实际缩放以样板为准。
- 底色不要烘焙固定阳光和重阴影；法线只表达浅岩层，不能生成石墙砌缝感。
- 石材不使用金属高光；粗糙度贴图以高粗糙度为目标，具体响应在Studio里看。
- 材质贴图若需要制作或上传，单独记录为待完成资产，不能把“纯色形体做了”报成“材质完成”。

### 5.4 原生路线的退出条件

一轮形体修正＋一轮材质修正后仍有以下任一问题，该模块转Blender，不继续靠加小块修补：

- 正面和斜视图仍像方盒拼墙，缺少连续岩层体积。
- 大面被明显小零件缝切碎；强阴影使所有拼接暴露。
- 单个标准岩壁模块需超过约35～45个可见零件才能接近轮廓。
- 横纹在相邻面明显断裂，材质无法合理接续。
- 同一模块一转镜头就露出穿插、锐利薄片或难以清理的布尔瑕疵。

上述数量是本项目制作约束，不是Roblox性能定律。是否好看仍由实际截图验收。

## 6. 地面制作分解

| 子件 | 造型／规格草案 | 表面与收边 |
|---|---|---|
| 主砖A/B/C | 约6×8，厚0.35～0.55；交错铺排 | 浅冷灰族 #BBC2CA／#ADB6C1／#C8CCD1 |
| 次级边带 | 宽约1.5～2.5 | 中灰 #8993A1，形成主路与站台的过渡 |
| 外路缘 | 宽约0.8～1.2，高于相邻沙地约0.35～0.6 | 深灰 #586270，厚度可见 |
| 转角路缘 | 直角为主，少量切角 | 用独立L形组合模板，避免缝隙 |
| 站台底座 | 总高约0.9～1.3 | 深底座、浅顶面；侧面有真实厚度 |
| 台阶 | 每级高约0.4～0.55，深约1.5～2 | 两级左右；必要处独立平滑碰撞面 |
| 中心标记 | 小型镐子标识嵌入中心砖 | 平面图案或简单几何；不做巨大纪念碑 |
| 沙地过渡 | 主路外缘保留窄沙地与少量植物 | 不出现大面积荧光绿草坪 |

制作要求：

- 先做3×3小块观察明暗，再铺T字转角验证边带转向。
- 砖缝宽初步0.06～0.12；由底层暗色基座显露形成，避免另建成百上千条黑缝。
- 砖块颜色以固定种子从3～5种接近色选择，避免棋盘格。
- 斑点、细裂纹使用共享贴图／材质，不用散布小球小方块模拟。
- 砖顶高度统一；平台覆盖处不再铺同高度地砖。重复生成不叠地板。
- 常见行走面碰撞连续；小斑点、贴花、视觉路缝不参与碰撞。
- 不能假设Part有通用倒角按钮。远景直边先靠厚度、收边和明暗成立；近景必要时少量楔块切角／编辑期CSG，超出合理复杂度转一个共享网格。
- 数值颜色只是起点。最终在已锁定光照下检查，不能靠过曝把砖洗成纯白。

## 7. 摊位、标牌、矿洞与次级细节

### 7.1 四个摊位：一个建筑族，四套配置

复用MarketStall、MerchantAssets、OreBuyer组合及挂点系统。不能为了设计稿再生一套不兼容摊位工厂。

| 子件 | 制作细节 | 验收重点 |
|---|---|---|
| 立柱 | 4根粗木柱；主柱宽约0.7～0.9；脚部厚包铁 | 不像细牙签，NPC和柜台不被遮死 |
| 横梁／斜撑 | 主梁高约0.8～1.1；斜撑约45° | 荷载关系看得懂，不悬空 |
| 柜台 | 台面厚约0.25～0.4；高度围绕原NPC手部位置校准 | NPC不被埋住，不悬浮；不独立放大NPC |
| 木板 | 3～5块大板为主，色差克制 | 细木纹从材质来，不贴满黑槽 |
| 篷布 | 主色＋奶油白条带；厚边、轻微下垂 | 条带沿布面连续，没有阶梯锯齿和重复穿插 |
| 包铁／铆钉 | 铁灰 #59616C；只放结构节点；每节点少量铆钉 | 不像塑料银球，不靠每块板都打钉增加细节 |
| 货品 | 复用OreCounterDisplay等已在库资产 | 露出柜台功能，不把杂物堆满 |
| 配色 | 回收绿、工具青、图鉴赭黄、背包柔紫 | 功能可辨，木框／铁件统一 |
| 交互挂点 | NpcMount、招牌、触发区、Prompt各自独立 | 改壳不破坏互动；建筑尺寸与Trigger不互相绑定 |

拆开建筑外壳和NPC再调尺寸，不对整个含角色的站点直接统一缩放。

### 7.2 标牌

- 练习区用大木／金属框牌，深蓝底 #24465F，奶白字 #F1F0DD；外缘可保留窄青光。
- 文案统一为“练习区”；矿洞“矿洞”；排行榜“排行榜”；回收“矿石回收”。
- 字体由SurfaceGui提供，中文文字可编辑；不把文字烘进模型贴图。
- 总标题、功能文字、数值说明三级，远处只需读清总标题。
- 支撑柱和横梁是结构的一部分，避免发光面板悬浮。
- 招牌不靠极亮发光使字变糊；从正常玩家视角、约40～60 studs观察可读性。

### 7.3 矿洞入口

- 两侧厚木柱＋顶部横梁＋斜撑＋铁角码，柱间净空与实际Gate对齐。
- 岩肩和拱顶使用围墙家族，不独立换一套圆润岩石风格。
- 门口到第一层Gate有明确的深色过渡，不出现能看到外面天空的接缝。
- 短轨道、枕木仅作为门口装饰，不延伸成新玩法；装饰不妨碍走路与射线。
- 整个Mine及标签、门、节点同步位移；Config.Hub.MineFront和实际坐标必须一致。
- 保留3层原有耐久和掉落配置，不在美术任务中改经济。

### 7.4 排行榜

- 保留Power／Coins标签与当前服务器范围，做两块相同结构的榜板。
- 两板共享宽大标题梁、厚木边框和金属角码；榜面深蓝灰。
- 平台用与练习区同族的石材和路灯。
- 面板方向朝主路；没有第三项数据则不出现伪造榜单。
- 具体名单区域保持可更新，不能被装饰模型替代。

### 7.5 光幕、路灯、植物、道具

- 售卖区保持连续渐变光幕、内外双框、偶发星星；沿用已有预制体。
- 初始光幕高度约1.5～2.5；绿框落在站点地面，不覆盖半条主路。具体透明度以已有满意版本为起点。
- 练习区只做低矮彩色边界，避免三块巨大炫光盖掉石头。
- 路灯由灯脚、短柱、灯罩、顶盖组成；共享模板，控制局部光范围；白天以视觉灯芯为主。
- 箱子2款、碎石2～3款、干草2款、小仙人掌2款即可。边角成组放，主路不撒满碎物。
- 装饰密度在墙脚和设施背后较高，玩家路径上较低；不使用数量堆砌填空。

## 8. 灯光与材质先统一，再批量生产

顺序：固定时间与镜头 → 中性地砖测试 → 围墙明暗 → 木／铁／布 → 绿框与小灯 → 最后整体轻调色。

初始试调方向：

- 保留午后日光；从当前Brightness约3.12开始逐步比较，不先给一组未经验证的“最终参数”。
- 中和当前偏暖Tint对冷灰石砖的染色，再判断是否需要提高对比度。
- 石材和布料避免镜面高光，金属只在包铁上少量出现。
- 暖黄灯光不能铺满整个地面；地砖亮面有细节，岩壁阴影仍可读。
- 只更新已存在的Atmosphere、ColorCorrectionEffect、ColorGradingEffect和Bloom，不复制第二套。
- 调整全局光照后必须回看A/B/C练习石、矿工衣服和铁镐，不能为了新墙把已认可资产照坏。
- 验收截图不通过图片后期再“修好”；交付画面必须来自Studio实机。

## 9. 工程组织与可复用接口

### 9.1 延续现有目录，逐项扩展

计划结构，不表示已经创建：

- ServerStorage.GameAssets.Environment.CanyonKit：岩壁、岩肩、顶部模块。
- ServerStorage.GameAssets.Environment.PavingKit：地砖、边带、路缘、台阶。
- ServerStorage.GameAssets.Environment.CampProps：路灯、箱子、植物、碎石。
- ServerStorage.GameAssets.Buildings.MarketStall：继续维护原模板与挂点。
- ServerStorage.GameAssets.Signs：维护原有牌库，添加统一木框版。
- ServerStorage.GameAssets.Interactions.AutoSellZone：继续作为唯一光区资产来源。
- MaterialService：只有需要自定义材质时添加CampSandstone、CampPaving、CampTimber等变体。
- ReplicatedStorage.Shared.CampArtConfig：计划存放统一调色、材质名、尺寸和模块版本。
- PrototypeConfig：继续管理Hub、Trainings、Layers等玩法与布局配置。
- CampEnvironment：负责从模板布置环境，不再把矿石拉长当岩壁。
- MerchantAssets：继续负责摊位克隆、配色、NPC挂点。
- ZoneVisuals：继续负责绿框／训练边界实例化。

只在现有模块职责确实不适合时才新增一个小模块，不增加平行的WorldManager、ZoneManager或MerchantFactory。

### 9.2 每项资产的记录字段

AssetId、AssetVersion、制作路线、源文件、模板路径、尺寸、Pivot、碰撞方式、材质、参考图、状态、实机截图、已知差异。

状态必须区分：Planned → NativeSample → StudioReviewed → ApprovedForRepeat → Integrated。转Blender时记录FallbackReason，保留失败样板截图作为对照。

### 9.3 模块接口约定

- 岩壁：地面接触中心为Pivot；局部-Z朝营地内侧；以挂点连接，而非每次猜坐标。
- 铺地：顶面高度和Footprint显式配置；避免依靠多个隐藏偏移量凑齐。
- 摊位：根Pivot保留兼容；NpcMount、SignMount、ZoneMount各自可编辑。
- 源模板无玩法脚本；交互沿用已有服务与标签，装饰模板不私自带独立循环。
- 装饰BasePart默认Anchored=true、CanTouch=false；碰撞／查询是否开启按用途设定。
- 矿石Target必须CanQuery；装饰不要抢射线；可走地面仍须被必要的地面查询识别。
- 不删除或重命名TrainingRock1/2/3、Target、Gate、已有训练／售卖／挖矿标签与BoardStat。
- 可视范围与真正Trigger分别记录，图形缩放后同步校核，不允许“框外也训练／站框里却不卖”。

### 9.4 编辑、保存和迁移

WorldBuilder当前遇到版本不符会重建并销毁旧Gem Gulch；不能简单升Version然后让它把用户手工修改一起覆盖。

先做选择性迁移：环境、铺地、标牌各自替换；功能站点保留身份及标签。更新本地src与Studio Source，保存原rbxlx。提供可单独复用的rbxmx资产库与制作清单。

每阶段修改前保存本地快照；Git只纳入本轮源文件、资产记录和必要交付物，不顺带提交旧废稿、缓存、密钥或整个工作目录。版本提交必须写明“样板／整图／实机验证”的真实状态。

样板包含：

## 11. Blender后备规格：只替换失败的那个部件

- 先做一个标准岩壁或一个篷布，不将整个营地烘成单一大网格。
- 不依赖生成三视图自动保证一致；按样板正面／侧面／俯视尺寸手工定形。
- 岩壁标准块初步目标约400～1200三角面；复杂转角约800～1800；篷布约200～600。均为本项目起始预算，最终按轮廓和实测调整。
- 宽面＋少量切角，保留横向层岩，不使用高密度噪声雕刻。
- UV尺度统一；尽量共享一套岩壁纹理和一套木／布纹理，不给每块墙独占一张大贴图。
- 石材色图为主；必要时补浅法线和高粗糙度，非金属。不把强灯光／投影烘到色图。
- 原点、朝向、尺寸遵守第9.3节；应用变换，检查法线、UV、重复面、开口和材质。
- 导出FBX，保留.blend源文件及贴图；导入后复核真实studs尺寸、纹理加载和碰撞。
- 保留独立简单碰撞代理，不能用复杂视觉网格堵住通路。
- 实际Studio效果不合格时回源文件修，不只通过全局发光／饱和度遮盖。

## 12. 质量验收：通过才批量复制

以下全部是目标，尚未执行，不能将“写进PRD”当作已测试。

| 检查 | 通过标准 | 不通过例子 |
|---|---|---|
| 围墙轮廓 | 正面与斜视均读得出大面、层岩、厚度和前后错落 | 仍是竖土豆、方盒墙、碎石堆 |
| 轮廓优先 | 关闭纹理或缩小截图，主体关系仍清楚 | 只靠纹理和小细节让画面复杂 |
| 地面明暗 | 缩小或看灰度仍能区分主路、边带、路缘 | 一片灰白；黑缝密集成网 |
| 纹理 | 近看有克制层次，远看无强烈重复花纹 | 大写实照片贴块；斑点像污渍 |
| 比例 | 玩家、NPC、柜台、石头和主路同框协调 | NPC被统一放大；石头缩成台面摆件 |
| 空间 | 出生可读矿洞方向；左练习、右排行；四角摊位易找 | 路太宽显空；岩肩挡招牌；转场迷路 |
| 接缝 | 固定及移动镜头无闪烁、漏天和明显穿插 | 同高度地砖重叠；墙后漏光 |
| 光照 | 冷灰砖仍是冷灰；木／石／铁可区分；旧角色质感保持 | 纯白过曝；全图发黄；石头塑料高光 |
| 交互 | 视觉边界与检测一致；离开即停；装饰不挡挖矿射线 | 光区和触发区错位，打中装饰 |
| 可复用 | 模板独立可克隆、改色、换尺寸；挂点有效 | 硬编码一堆绝对坐标，只能用于一个位置 |
| 性能 | 记录相同设备／画质／镜头下前后表现，再判断 | 只报零件数或“看起来流畅”就声称优化完成 |

初始制作预算：标准岩壁模板优先不超过35～45个可见原生零件；摊位外壳优先约60～90个可见零件（不含NPC与既有交互特效）；材质初始以共享1024²为主。全场预算在样板实测后锁定，不提前保证FPS。大批透明层、可投影小灯、每帧运行的装饰逻辑均需控制。

## 13. 功能回归清单

美术批量落地后最少验证：

- 出生／重生在可走地面，玩家穿着不被新环境逻辑覆盖。
- 三个练习区位置、朝向、TrainingIndex对应正确，自动敲击、停止训练和+1／+3／+6原逻辑保持。
- 手动点击加力量、铁镐扛肩和挥镐表现保持，装饰不拦截目标射线。
- 挖开第一层门，通往后两层的地面／门／目标无错位。
- 背包满5块与矿石售价逻辑保持，进入绿框售卖，空背包不重复结算。
- 工具铺Prompt及现有升级可用；筹备摊位不伪装成已实现功能。
- 两项服务器排行榜更新，板面朝向及可读距离正常。
- 正常走路、跳跃、绕台阶、贴墙移动无卡住；边界不会掉出地图。
- 服务端与客户端分别检查Output；只把本轮新增报错算本轮回归，既有问题单独记。
- 桌面视角与一次移动设备尺寸／操作检查；没有跑过的模式明确写“未测”。
